# TRACE｜调查闭环一致性（本轮实测）

## V23 为什么出现两个结论

`GET /v1/runs/:id/trace/assessment` 优先返回**冻结的核验快照**（`verify-step`）或最后一次 `/trace/reassess` 的结果，
而 `/trace/auto`、`/trace/followup` 写入的是追加检索证据后**现算**的 `buildAssessment(run)`。
两条读取路径的数据源不同 → 补查拿到 contradicted、刷新又回到 insufficient。

## 修复

1. **统一当前结论**：`/trace/assessment` 改为始终 `buildAssessment(run)` 现算（包含首次核验、追加检索、人工修正、重算），
   并额外返回 `verifySnapshotAt / reassessmentAt / followupCount / correctionCount` 供追溯。
   历史结论不被覆盖：核验快照、重算记录、追加检索证据仍各自保留在 evidence 里。
2. **补查决策用最新评估**：`trace/auto` 每轮开头重新 `buildAssessment`，`askNext(snapshot)` 基于刚更新的来源判断缺口
   （V23 用的是循环外的旧事实，第二轮看不到第一轮的新资料）。
3. **同页支持+反驳不直接算支持**：同一页面既有 direct_support 又有 direct_refute 时，
   改判为 partial 并写明两侧原句，不再按「支持分更高」定案。
