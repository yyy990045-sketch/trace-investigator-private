# TRACE｜统一入口、传言核查与来源层级（本轮实测）

## 修改

1. **首页统一成一个输入**：标题「你想查清什么？」，一个输入框 + 一个「开始调查」按钮，
   按内容自动分流（影视 → 候选追查，公开信息 → 出处核验）；两种手动方式移入「高级：手动指定调查方式」折叠区，普通用户不必理解分流。
2. **传言/疑问式说法改写**（`query-plan.deriveClaims`）：新增「网传 X，是真的吗？」「有人说 X，可信吗？」
   路径——去掉「网传/有人说」和疑问结尾，把中间那句断言作为待核查对象（之前会把整句问句当事实，导致一条都对不上）。
3. **型号不是数量**（`analyze.numbers`）：PS4 / iPhone 15 / Switch 2 / 4K 这类型号数字不再被当成「数量断言」。
   修复前「索尼 PS4 已经正式停产」会被判成「数量条件未能完整识别，不能判断」，整条说法直接证据不足。
4. **来源层级**（新 `apps/trace/src/source-tier.ts`）：官方 / 权威机构 / 媒体 / 其他；
   结论里直接写明「依据来自媒体报道，尚未找到官方原始公告」或「依据中有官方原始页面」。

## 实测

- **A 影视错误记忆**：`ambiguous`「最可能是《解密》，但还有 2 条情节没在资料里核到；《暗算》也需要排除」，
  并列出《解密》= 电影/2023、主演名单里没有布拉德·皮特。
- **B 公开信息（PS4 是否停产）**：修复型号误判后出现了真实支持证据（百科：PS4 相关条目），
  但只有搜索摘要、没有官方原文正文 → 结论仍是「证据不足」，并按层级说明「支持性来源只有搜索摘要」。
- **C 咖啡与寿命**：仍为「证据不足：没有任何来源与待核查事实形成可比对表述」——**未解决**，
  这条说法需要流行病学原文，当前 fact 流程的匹配规则接不住。
