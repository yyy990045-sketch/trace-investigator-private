## 一、产品介绍

**TRACE｜溯证**：面向信息真实性调查的 AI 搜索侦探。

核心流程只有一条：

```
输入待核查信息 → 元宝搜索原始出处 → 证据与条件核验 → 调查结论
```

结论只有四种状态：**证实 / 证伪 / 证据不足 / 信息过期**；证据不足时同时列出"还缺什么"。

## 二、真实能力（只写已实现、可指回记录的）

| 能力 | 实现方式 | 可核验处 |
|---|---|---|
| 元宝 SearchPro 真实搜索 | 每条检索式单独记录 requestId、HTTP 状态、返回条数、耗时；失败/限流如实标注 | 报告与档案的「检索技术记录」 |
| 来源追踪 | 每条证据带 URL、站点、原句；区分「网页正文」与「搜索摘要」 | 案例页证据卡、档案 JSON |
| 日期条件核验 | 从同一条原文里分别抽取「通过/公布」与「施行/生效」日期，再与待核查日期比对 | 锁定案例① |
| 数字条件核验 | 把数字绑定到主体+指标+年份+单位后比较；「超过 1300 万」不等同「1300 万」 | 锁定案例②、单元测试 |
| 范围条件核验 | 局部（单条干线/单城市）证据不计入"全国"说法的支持或反证 | 锁定案例③ |
| 证据冲突处理 | 两组不同口径的数字并列保留，不认定谁算错；无法解释时写「具体差异原因尚未核实」 | 锁定案例② |
| 不确定性解释 | 结论句说明为什么不下判断、还缺哪些证据、来源为何不能算独立 | 三个锁定案例页面 |
| 调查记录与档案 | 每次调查生成 Markdown + JSON 档案，含来源、逐条判断、检索记录，可下载 | `/artifacts/<runId>/调查档案.md` |
| 线索发现与主动消歧（附加） | 模糊线索 → 候选发现 → 有向关系（改编自/续集/翻拍/别名）→ 缺证据时自动补查 | 线索调查页 |

**不声称**：全领域准确率、自动判定真理、自主学习系统。以上能力只在三个锁定案例与既有测试覆盖的范围内被验证。

### 案例② 新能源汽车产量两组数字

- 问题：为什么 2024 年中国新能源汽车产量有 1288.8 万辆和 1316.8 万辆两种说法？

  - 央视网转述中汽协：「2024年…产销量分别完成 1288.8 万辆和 1286.6 万辆」

## 四、系统说明（能力边界，务必按此表述）

- **真实搜索由本机 Runtime 执行**：元宝 SearchPro 的 Key 只存在本机 `.env.platform`，前端不接触。
- **公网展示复用真实历史调查结果**：页面数据由导出脚本从本机 SQLite 中已完成的调查生成，导出前经过敏感信息审计（密钥、本机路径、手机号/证件号脱敏）。
- **公网只读版不会产生新的检索**：页面上没有可提交的搜索框，示例入口打开的是当时那次真实调查的回放；页面明确标注「历史调查记录（只读）」。
- **原始记录与展示经过脱敏**：网页正文里出现的第三方联系方式在展示数据中被替换为「[手机号已隐去]」等标记，证据含义不变。

## 六、本机如何运行（复现真实检索）

```bash
git clone https://github.com/yyy990045-sketch/trace-investigator-private.git
cd trace-investigator-private
npm ci
cp .env.platform.example .env.platform   # 填 PLATFORM_WSA_API_KEY 与模型配置（仅本机）
npm run start:local                      # Runtime 4313 / TRACE 4316
```

浏览器打开 http://127.0.0.1:4316 输入任意待核查信息，即可发起真实检索；未配置 Key 时入口会直接显示阻塞并拒绝给出联网结论。
