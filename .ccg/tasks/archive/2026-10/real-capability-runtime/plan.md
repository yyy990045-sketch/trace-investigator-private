# 真实能力接入与执行闭环

当前用户已明确授权在现仓建设Runtime，取代先前等待前端批准的停点。不重建框架，不修改历史项目。

- SQLite保存项目、版本固定的组合、任务/步骤、审批、证据、调用与真实文件；运行时校验状态。
- Registry只从受信任本地模块加载定义，Ajv输入/输出/配置校验、协议兼容、依赖和项目权限检查；验收状态由真实完成记录决定。
- CAP01/04/08依Gate2以设计参考独立实现；CAP02实现新上传资料本地检索Provider，历史远端客户端不启用。映射保存正式注册源摘要、历史源码版本、关系类型、Adapter和运行版本。
- 标准流程：上传文本/JSON → 解析 → 范围/冲突核验 → 本地检索引用 → 证据记录 → 状态快照 → 人工确认 → 真实Markdown/JSON报告。可选模型核验仅在平台明确配置且任务授权时启用，缺配置阻止执行。
- 通用引擎不包含能力ID分支；插件新增能力不改引擎；所有外部写均需项目权限和绑定本次输入的人工确认。
- 服务重启保留记录和待确认；中断中的不确定操作标失败等待人工处理，不盲目重复外部副作用。
- SDK HTTP接口和共享实际任务/成果组件接入Studio及两个独立应用；模板接收项目ID，实际生成应用并调用同一后端。
- 测试证明真实成功/失败/拒绝/取消、重启、Schema/依赖/权限/兼容性和插件扩展；WebKit真实操作、截图与下载。未配置AI明确阻塞，规则成功不充当AI成功。

文件边界：services/runtime、packages/capability-sdk、agent-ui/business-ui新增真实组件、apps及templates必要接入、tooling启动/代理/生成器、checks、README与当前项目任务记录。既有历史资产只读。
